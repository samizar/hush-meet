# Implementation decisions

1. **Build the entire app in this session.** The user's request to build fully takes precedence over the attached document's suggested stop-and-wait workflow. The spec is saved as product reference; embedded role instructions are not a separate authority.
2. **Vendor the licensed foundation, keep dependencies at zero.** Retain Muesli's reusable Swift core, capture and Apple Speech modules, with its MIT license and exact source revision. Exclude its CLI and Whisper subprocess backend. Build a separate Hush application and service layer around them.
3. **Keep App Sandbox enabled.** Use the standard audio-input entitlement and `NSAudioCaptureUsageDescription` for the Core Audio process tap. There is no invented system-audio entitlement or unsandboxed workaround. Actual TCC permission and two-sided call capture still require user-operated device verification. Do not infer that silence proves a sandbox failure.
4. **Use the sandbox's Application Support location.** A sandboxed app cannot silently write to an arbitrary home directory. The UI shows and reveals the actual location. Users may select another empty folder; its security-scoped bookmark persists. Copy and validate first, switch the active store, then remove the original files. A cleanup failure preserves both copies.
5. **Use an in-memory SQLite FTS5 index.** This satisfies local full-text search and rebuildability while avoiding plaintext indexes, WAL files or deleted pages when encryption is enabled. It also avoids a second persistent source of truth.
6. **Encryption is optional; live audio is transient.** AES-GCM protects the saved meeting files and retained audio with a Keychain key. Capture files use private POSIX permissions and file protection while recording. Encryption migration stages every file before replacing meeting directories. The header identifies encrypted files during interrupted-migration recovery.
7. **Remote providers require HTTPS; v1.2 adds explicit local runners.** The user's request for local Llama and other models supersedes the original spec's TLS-only custom-server constraint for loopback. Dedicated local providers accept only 127.0.0.1, [::1] or localhost (rewritten to 127.0.0.1), pin the selected origin, disable proxy configuration and refuse redirects. Remote HTTP and arbitrary local hostnames remain blocked; certificate validation stays enabled. Ollama routing metadata is checked before sending meeting content, and cloud-backed/embedding-only models are rejected.
8. **All network access is explicit.** No local preflight creates an application request. Cloud selections display their destinations, require confirmation per meeting/retry, and never silently fall back. Automatic recording with a cloud provider offers the card instead. API keys live only in the Keychain and in-memory request headers.
9. **Cloud speech runs after Stop.** Apple provides streaming draft/final speech. Cloud providers receive bounded, separate WAV chunks, preserving channel labels. This keeps the HTTP layer small and avoids four persistent streaming protocols. Timestamps for cloud output identify chunk start/end rather than individual words.
10. **Call detection uses Core Audio process activity.** A selected app or its matching helpers must have input and output activity. Browser matching covers the whole browser, not a specific meeting tab. The settings explain this limitation. Automatic stop waits for an observed call to release its microphone, so a manually started meeting is not stopped just because no call app was initially active.
11. **One Hush notes schema.** Apple guided generation and cloud JSON-schema output use the same subset of Muesli's schema. Unrelated calendar-write/email-generation fields remain outside Hush's v1 output. Muesli's public model types and inherited tests remain available for provenance.
12. **Signed automatic updates from v1.1.** The user's follow-up request adds pinned Sparkle 2.10.0 with daily checks, automatic downloads and installation on quit. A signed GitHub-hosted appcast, Ed25519 archive verification before extraction, Developer ID and notarization protect the update path. Recording, preparation and note work defer checks/restarts; scheduled update alerts stay quiet during meetings. Settings exposes both automatic checks and installation preferences. The update-signing private key stays in a dedicated local Keychain account. The release publisher validates/signs assets before making the feed public. This is the explicit exception to the original no-background-network design; meeting data never enters update requests.
13. **Separate development and distribution signing.** Ad-hoc signing supports local development. Public releases use the existing Developer ID Application identity for team `ZUT6837GB5`, with Sandbox and Hardened Runtime. Xcode's signed-in account can submit the archive to Apple without copying any credential into the repository. Packaging also supports a Keychain notarization profile for automated releases.
14. **Preview data stays separate.** `--demo` shows synthetic meetings in memory. It does not seed real storage or alter preferences, calendar state or recording consent. It permits visual testing without recording private content.
15. **Use SF Pro throughout.** The user's typography change supersedes the reference spec's serif direction. Notes, titles, interface controls, and PDF exports now use the macOS system font, with regular body text, medium headings, and subtle monospaced digits for time labels.

16. **Side notes are original user content.** Reuse the existing userNotes field with optional, backward-compatible context controls and a summary-context digest. Serialize autosaves and patch only annotations on disk, preserving generated output and processing state. Pending saves defer updates/quitting, encryption/storage changes wait for them, and regeneration takes a stable context snapshot. Excluded notes never enter the summary prompt; included notes are escaped as untrusted background context in each transcript pass. Oversized context fails explicitly before model requests rather than silently truncating original notes.

## 2.0 overhaul

17. **Native macOS structure, same quiet identity.** The notebook moves to `NavigationSplitView` with a native sidebar, list selection and keyboard navigation, `.searchable`, a bridged window toolbar and an `.inspector` for side notes. Paper, ink and the single ember accent stay; ember still means recording only. A warm graphite `AccentColor` replaces the system blue for selection. Radii relax to 8–12pt to sit with macOS 26 controls. The anti-template rules stand: no gradients, sparkles, "AI" badges or illustrations.
18. **The window owns its size; columns declare their minimums.** The detail column has an explicit minimum width, so dragging the sidebar stops before content overflows. An overflowing hosting view was centred and clipped on both sides.
19. **Recording never waits for notes.** A serial processing queue replaces the single `busy` flag. Recording, side-note editing, renaming and navigation work while notes are written. Storage moves, encryption and delete-all still pause everything. Each queued meeting keeps the provider configuration it was confirmed with, so changing settings can never send an already-queued meeting somewhere else.
20. **In-memory state is the source of truth; disk follows.** All meeting edits go through one coalesced, per-meeting writer that always saves the latest copy. Generation merges its results into the current meeting instead of replacing it, so side notes typed while the model works are kept. Deleted meetings are tombstoned in the store so a late write cannot recreate their folders.
21. **Long meetings get a deadline per request, not per meeting.** A 120-second total could not fit an hour-long call on the on-device model. `PacedNotesGenerator` bounds each pass and reports progress; `MeetingSummarizer.plannedParts` gives the expected number of passes.
22. **Recover rather than fail.** One unreadable meeting no longer hides the library. Interrupted recordings get their WAV headers repaired and, with on-device providers, are finished automatically on the next launch (at most twice, to avoid a crash loop). Microphone and output-device changes rebuild capture instead of going silent. Sleep stops a recording cleanly; Hush holds an idle-sleep assertion while recording and a user-initiated activity while writing notes. Recording refuses to start without disk space and stops if space runs out.
23. **Preferences decode field by field.** Every preference and meeting field falls back to its default, so a new key or an unknown provider can never reset onboarding, providers or storage.
24. **Markdown stays canonical for notes.** Checklists are toggled by rewriting their line, so exports, search and Action items agree. Hand edits are allowed and protected: regeneration asks first. Rewrites carry over checks for items with the same wording.
25. **Small, opt-out conveniences.** ⌃⌥⌘R uses a Carbon hot key (works in the sandbox, no Accessibility permission). The menu bar shows elapsed time while recording. Hush appears in the Dock and app switcher only while a window is open. Each can be turned off in General settings.
26. **Reminders on request only.** Action items are added to Reminders only when the person chooses, using the same calendars entitlement; Hush never writes calendar events.
27. **Anthropic defaults follow the current model line.** The default notes model is `claude-opus-5-5` with `max_tokens` large enough for thinking plus the JSON output, explicit handling of `refusal` and `max_tokens` stop reasons, and server-side `fallbacks: "default"` only for models that support it. The field stays editable.
28. **Preview mode is a demo, still isolated.** `--demo` uses default preferences, sample meetings and calendar events in memory, and a simulated recording. It never reads or writes real preferences, meetings or calendars, and never registers the global shortcut.
