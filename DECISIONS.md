# Implementation decisions

1. **Build the entire app in this session.** The user's request to build fully takes precedence over the attached document's suggested stop-and-wait workflow. The spec is saved as product reference; embedded role instructions are not a separate authority.
2. **Vendor the licensed foundation, keep dependencies at zero.** Retain Muesli's reusable Swift core, capture and Apple Speech modules, with its MIT license and exact source revision. Exclude its CLI and Whisper subprocess backend. Build a separate Hush application and service layer around them.
3. **Keep App Sandbox enabled.** Use the standard audio-input entitlement and `NSAudioCaptureUsageDescription` for the Core Audio process tap. There is no invented system-audio entitlement or unsandboxed workaround. Actual TCC permission and two-sided call capture still require user-operated device verification. Do not infer that silence proves a sandbox failure.
4. **Use the sandbox's Application Support location.** A sandboxed app cannot silently write to an arbitrary home directory. The UI shows and reveals the actual location. Users may select another empty folder; its security-scoped bookmark persists. Copy and validate first, switch the active store, then remove the original files. A cleanup failure preserves both copies.
5. **Use an in-memory SQLite FTS5 index.** This satisfies local full-text search and rebuildability while avoiding plaintext indexes, WAL files or deleted pages when encryption is enabled. It also avoids a second persistent source of truth.
6. **Encryption is optional; live audio is transient.** AES-GCM protects the saved meeting files and retained audio with a Keychain key. Capture files use private POSIX permissions and file protection while recording. Encryption migration stages every file before replacing meeting directories. The header identifies encrypted files during interrupted-migration recovery.
7. **HTTPS remains mandatory, including custom servers.** Ollama and LM Studio need TLS termination. Hush does not exempt loopback from HTTPS or accept self-signed certificates. This follows the spec's explicit HTTPS boundary.
8. **All network access is explicit.** No local preflight creates an application request. Cloud selections display their destinations, require confirmation per meeting/retry, and never silently fall back. Automatic recording with a cloud provider offers the card instead. API keys live only in the Keychain and in-memory request headers.
9. **Cloud speech runs after Stop.** Apple provides streaming draft/final speech. Cloud providers receive bounded, separate WAV chunks, preserving channel labels. This keeps the HTTP layer small and avoids four persistent streaming protocols. Timestamps for cloud output identify chunk start/end rather than individual words.
10. **Call detection uses Core Audio process activity.** A selected app or its matching helpers must have input and output activity. Browser matching covers the whole browser, not a specific meeting tab. The settings explain this limitation. Automatic stop waits for an observed call to release its microphone, so a manually started meeting is not stopped just because no call app was initially active.
11. **One Hush notes schema.** Apple guided generation and cloud JSON-schema output use the same subset of Muesli's schema. Unrelated calendar-write/email-generation fields remain outside Hush's v1 output. Muesli's public model types and inherited tests remain available for provenance.
12. **Signed automatic updates from v1.1.** The user's follow-up request adds pinned Sparkle 2.10.0 with daily checks, automatic downloads and installation on quit. A signed GitHub-hosted appcast, Ed25519 archive verification before extraction, Developer ID and notarization protect the update path. Recording, preparation and note work defer checks/restarts; scheduled update alerts stay quiet during meetings. Settings exposes both automatic checks and installation preferences. The update-signing private key stays in a dedicated local Keychain account. The release publisher validates/signs assets before making the feed public. This is the explicit exception to the original no-background-network design; meeting data never enters update requests.
13. **Separate development and distribution signing.** Ad-hoc signing supports local development. Public releases use the existing Developer ID Application identity for team `ZUT6837GB5`, with Sandbox and Hardened Runtime. Xcode's signed-in account can submit the archive to Apple without copying any credential into the repository. Packaging also supports a Keychain notarization profile for automated releases.
14. **Preview data stays separate.** `--demo` shows synthetic meetings in memory. It does not seed real storage or alter preferences, calendar state or recording consent. It permits visual testing without recording private content.
15. **Use SF Pro throughout.** The user's typography change supersedes the reference spec's serif direction. Notes, titles, interface controls, and PDF exports now use the macOS system font, with regular body text, medium headings, and subtle monospaced digits for time labels.
